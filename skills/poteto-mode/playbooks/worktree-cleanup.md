### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh` (principle-build-the-lever). It reads paths from `git worktree list`, never hand-typed, since a hand-typed `<repo>-worktrees/x` misses one that lives inside the repo at `.worktrees/<repo>/x` or under `/tmp/<task>/` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest session that touched it, then suggests a bucket. The scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active sessions are the real artifact (principle-prove-it-works). Get that set from the user or the sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins. The audit's `verify-recent-chat` bucket is a prompt to check, never a verdict: its last-session column is best-effort, so confirm by hand.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the sessions and report whether the session is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, exports are bulk). Use `opencode session list` to find candidate sessions and `opencode session export <sessionID>` to read one, matching on the worktree path in the export; do not read the session store directly and do not export unrelated projects. A pinned session spawns review and repro worktrees into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. Never delete uncommitted work on your own judgment — committing it as `wip:` first is always available and is the reversible option. `scratch:N` is untracked throwaway, safe to drop, but name the files. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Creation and removal both stay idempotent (principle-make-operations-idempotent): re-running a prune on an already-pruned path is a no-op that reports the path as absent, never an error and never a different target. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. Those commands are macOS-only and this machine is Linux, so expect them to be absent and skip straight to the cross-platform reclaimers. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, opencode's own data under `~/.local/share/opencode` (its `opencode.db` and any leftover log or snapshot directories), package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep, and never touch the session database itself while a session is live.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which session, or uncommitted work).
